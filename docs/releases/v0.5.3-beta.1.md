## Changes / 本版變更

- **Built-in reversible enhancement.** On an explicit project-prompt rewriting request,
  keep the selected original, one editable proposal and important changes/reasons visible.
  Distinguish user facts, verified facts, unknowns and suggestions. Accept partial edits,
  another attempt or the original; rejected additions must stay out of subsequent work.
  No separate `prompt-refiner` installation is required.
- **Preserve the task boundary.** A rewrite-only request does not execute its contents,
  even after wording adoption. Product-scope agreement and operation authority remain
  separate. Reuse substantive confirmation that already covers the actual scope.
  Restoring wording does not undo code or external actions.
- **Explain useful choices.** Give one concrete reason for a consequential question or
  capability choice so the owner can correct direction; avoid repeated invocation receipts.
- **Present for a purpose.** Explore with provisional sketches, compare with tables,
  and use self-contained SVG/HTML for structure, sharing or meaningful interaction.
  Essentials stay inline. Views identify the same Brief/SPEC revision and retain its
  uncertainty, permissions, statuses and dependencies. Escape source markup and perform
  actual browser checks before claiming visual validation.
- **Honest model handling.** Use the current host model by default. A named model requires
  a verifiable callable route; unavailable or failed routes are reported, with no silent
  model substitution, retry or global settings change.

明確說「幫我增強提示詞」就可以直接改寫；原話與改稿可比較、可局部修改或返回。
只改提示詞就停在這裡，不把「這樣寫清楚了」當成執行授權。
一般項目仍先探索、回述與必要草圖，在共同理解及第一版範圍確認後才生成首張行動卡。
重要提問附一句用途；圖文按需要產出，不以更多附件代替對話。

## Verification boundary / 驗證邊界

The release gate requires package/readiness validation, scoped interaction replays,
source-matched draft visual samples and a completed Claude Code red-team review
of the final candidate with no unresolved blocking findings. The final release body
records the verdict, report digest and artifact checks; listing a check here is not
a claim that an unfinished review passed. These are limited engineering prechecks, not human acceptance or a controlled
demonstration of better prompting, lower cost or improved learning.

The two case topics are a desktop application's GUI discovery/prototype and this
Skill's own iteration. The second is dogfooding, with familiarity and self-evaluation
bias. Controller answers are simulated; no model reply is labelled as a human decision.
Comparisons retain the same initial material and inherited host configuration, but
do not establish a clean wire-level model identity, billing comparison or no-skill isolation.

兩案用於檢查互動與呈現，沒有因此完成真實原生 GUI 改版，也未驗證真人更容易理解。
相同模型與初始材料的有限回放，不能證明候選普遍優於現版或原生宿主。
渲染檢查只適用於被打開檢查的樣本，不保證將來每次生成或所有宿主都相同。

Human comprehension, 24–72-hour learning transfer, implicit dispatch, cross-model
reliability, live native application implementation and large-project effectiveness
remain unverified. A model audit cannot certify those outcomes.

本版沒有原生輸入框按鈕、真正 GUI undo、獨立 server、任意模型切換、背景監督、
全域 hook、原生自適應卡片或新增 runtime dependency。實際工具與預覽仍由宿主提供。

## Install and roll back / 安裝與回復

Download **`cyber-age-sop-v0.5.3-beta.1.zip`**, verify it against `SHA256SUMS.txt`,
and install its single `cyber-age-sop/` folder using your Agent/IDE's Skill mechanism.
For local Codex, the usual location is `~/.codex/skills/cyber-age-sop/`.
Back up the whole old folder outside the scan path, then replace the entire folder;
do not overlay references from different versions. Start a new chat for a clean trial.

下載 ZIP 並核對校驗值，備份舊版後整個目錄替換，建議開新 chat 測試。
如需回復，以完整舊備份替換。本版發布不代表各宿主已自動安裝更新。

- `.zip`: installable Skill with `LICENSE` and `NOTICE` / Skill 安裝包與授權聲明。
- `.tar.gz`: full public source snapshot / 公開倉庫快照。
- `SHA256SUMS.txt`: checksums for both archives / 兩個附件的校驗值。

## Try and report / 試用與回饋

Try: "Enhance this project prompt, but do not execute it. Keep my original,
show important changes and reasons, and leave unknowns open." Reject one suggestion,
then ask for the original. If you continue the project, check whether only accepted
meaning reaches the Brief, tasks and views. Tell us when an explanation or visual
adds burden instead of clarity.

可試：「幫我增強這段項目提示詞，先不要執行；保留原話，展示重要差異與理由，未知保持未知。」
試著拒絕一項建議，再要求用回原文。若開始項目，檢查後續有沒有混回拒絕的內容。
也請記下不開附件能否明白下一步、圖文是否真的更清楚，以及多問或多文件造成的負擔。
