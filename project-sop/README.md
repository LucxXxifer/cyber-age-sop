# Cyber-Age Project SOP

This directory contains the durable project-record layer that accompanies the
`cyber-age-sop` runtime Skill. The layer is a framework for deep discovery,
boundary clarification, design decisions, and handoff. It is not a project
management platform or a domain solution.

## Documents

| Document | Purpose |
|---|---|
| `reference-project-template.md` | Reusable presentation structure and explicit non-copy rules |
| `cyber-age-project-sop类型定义.md` | Project type, task profiles, metadata, and evidence contract |
| `cyber-age-project-sop完整鏈路.md` | End-to-end lifecycle from anchor to review |

The documents use a representative project as a presentation reference only.
They do not transfer any project's devices, topology, code, release history,
dates, or field observations to another project.

## Use Order

1. Read the reference-sample boundary.
2. Choose the target project's primary task profile.
3. Build a fresh Project Anchor from the target project's own material.
4. Add research or design checkpoints only when they can change the decision.
5. Create an Agent Brief and explicit evidence boundary.
6. Verify the result independently.
7. Write the target project's own project page and evidence appendix.

## Scope and Boundaries

The project layer scales from a small task to a large system or a program of
projects. Use `project_scale: fast | standard | large | program` when the
amount of coordination changes.

It can coordinate software, infrastructure, documentation, agent workflows,
art and design production, AI-generated media, and games. It does not replace
the domain engine or the human/domain review needed by those activities.

GitHub is the versioned execution and release surface. Obsidian is the
human-readable project and evidence surface. Keep the two connected, but do not
copy private context into a public repository.
